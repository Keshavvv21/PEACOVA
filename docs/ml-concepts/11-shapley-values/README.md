## 1. Origin: Cooperative Game Theory

Shapley values originate in **cooperative game theory**, introduced by Lloyd Shapley in his 1953 paper *"A Value for n-Person Games"* (Shapley won the 2012 Nobel Memorial Prize in Economic Sciences, partly for this line of work). The problem Shapley solved is deceptively simple to state:

> A group of `n` players cooperates to produce some total value (a payoff). Different subsets ("coalitions") of players, if they worked together, could have produced different amounts of value. Given this, how should the total payoff generated by the *full* coalition of all `n` players be **fairly divided** among them?

Formally, a **cooperative game** (also called a *coalitional game*) is defined by:

- A set of players `N = {1, 2, ..., n}`.
- A **characteristic function** (or **value function**) `v: 2^N -> R`, which maps every possible subset (coalition) `S subseteq N` to a real number `v(S)` — the total value that coalition `S` can achieve on its own, without help from the other players.
- By convention, `v(empty set) = 0` — a coalition of nobody produces nothing.

The question is: how much of `v(N)` (the value of everyone cooperating) should each individual player `i` receive as their fair share, call it `phi_i`?

This is a non-trivial allocation problem because players are not interchangeable, and a player's contribution generally depends on *which other players are already present*. A classic illustrative example: three people jointly own a taxi business. Player A owns the license, player B owns the car, player C can drive. Alone, none of them can earn anything (`v({A}) = v({B}) = v({C}) = 0`). Any two together might unlock partial value (e.g., a license-holder + driver could rent out the license and still earn something with a hired car), and all three together generate the full profit `v({A,B,C})`. Simple proportional splits (e.g., "split equally" or "split by revenue produced alone") fail to capture how much each player's *presence* actually changes what a coalition can achieve. Shapley's insight was to define a player's fair share as the average of their **marginal contribution** — the amount they add to a coalition — computed consistently across *every possible order* in which the coalition could be assembled.

This is precisely the property that makes Shapley values transferable, decades later, to machine learning: a trained model's prediction is treated as the "total payoff" of a coalition of "players" (the input features), and we want to know how much of the prediction's deviation from a baseline is fairly attributable to each feature.

## 2. The Formal Shapley Value Formula

For a game with player set `N`, `|N| = n`, and characteristic function `v`, the Shapley value of player `i` is:

```
                     |S|! (n - |S| - 1)!
phi_i(v)  =    sum   --------------------  *  [ v(S union {i}) - v(S) ]
             S subseteq N \ {i}      n!
```

Or in a more compact/traditional notation:

```
phi_i = (1/n!) * sum over all permutations (orderings) pi of N of  [ v(P_i(pi) union {i}) - v(P_i(pi)) ]
```

where `P_i(pi)` is the set of players that precede player `i` in ordering `pi`.

These two formulas are equivalent — the first sums over *subsets* `S` and weights each subset by a combinatorial factor; the second sums over *permutations* (orderings) and takes a plain average. It is worth deriving the equivalence, because doing so is what actually makes the formula intuitive.

### 2.1 The permutation view (the intuitive derivation)

Imagine that players join the coalition one at a time, in a uniformly random order — i.e., pick a uniformly random permutation `pi` of the `n` players out of the `n!` possible orderings. As each player joins, they receive credit equal to the **marginal contribution** their arrival creates: the value of the coalition right after they join, minus the value right before they join.

For a fixed ordering `pi`, if player `i` arrives when the set of players already present is `S = P_i(pi)`, then player `i`'s marginal contribution in that ordering is:

```
v(S union {i}) - v(S)
```

The Shapley value is simply the **average marginal contribution of player `i`, averaged uniformly over all `n!` orderings**:

```
phi_i = (1/n!) * sum_{pi in all orderings} [ v(P_i(pi) union {i}) - v(P_i(pi)) ]
```

This is the cleanest way to state *what a Shapley value actually is*: it is not "player i's contribution in some canonical order," it is the expected marginal contribution when players are added in a **random** order, averaged fairly over every possible way the coalition could have been built up.

### 2.2 The subset-weighted view (the computational form)

Now regroup that sum by which *subset* `S` precedes player `i`, rather than by which full permutation produced that subset. For a given subset `S subseteq N \ {i}` of size `|S| = s`, how many of the `n!` orderings have exactly the players of `S` arriving before `i` (and the rest arriving after)?

- The players in `S` can be arranged in front of `i`, among themselves, in `s!` ways (any internal order of `S` is fine, as long as they're all before `i`).
- The remaining players — those in `N \ S \ {i}`, of which there are `n - s - 1` — can be arranged after `i` in `(n - s - 1)!` ways.
- Player `i` itself sits in a fixed position: immediately after all of `S` and before all the rest.

So the number of orderings for which `i`'s "predecessor set" is exactly `S` is `s! * (n - s - 1)!`. Dividing by the total number of orderings `n!` gives the *probability* that a uniformly random ordering produces exactly predecessor set `S`:

```
Pr[predecessors of i = S] = s! (n - s - 1)! / n!
```

Substituting this weight for each subset recovers the subset form:

```
phi_i = sum_{S subseteq N \ {i}}  [ |S|! (n - |S| - 1)! / n! ] * [ v(S union {i}) - v(S) ]
```

### 2.3 Reading each term

| Term | Meaning |
|---|---|
| `S subseteq N \ {i}` | Any coalition of the *other* players, not containing `i`, that could exist "before `i` joins." Ranges over all `2^(n-1)` such subsets. |
| `v(S union {i}) - v(S)` | Player `i`'s **marginal contribution**: how much value is added specifically by `i` joining coalition `S`. This is the causal quantity of interest. |
| `|S|!` | Number of ways to order the players *already in* `S` before `i` arrives. |
| `(n - |S| - 1)!` | Number of ways to order the players *not yet in the coalition* (excluding `i` and `S`), who arrive after `i`. |
| `n!` | Total number of possible orderings (permutations) of all `n` players — the normalizing constant. |
| `|S|!(n-|S|-1)!/n!` | The probability of coalition `S` forming immediately before `i`, if all `n!` orderings are equally likely. Equivalently, `1 / (n * C(n-1, |S|))`. |

**Intuition, stated plainly:** the Shapley value of player `i` is a *weighted average of `i`'s marginal contribution*, taken over every possible coalition `i` could join, where the weighting corresponds exactly to sampling a uniformly random order of arrival for all `n` players. Coalition sizes near the two extremes (`|S| = 0` or `|S| = n-1`) get more relative weight per subset than middling sizes, because there are fewer orderings that produce very small or very large predecessor sets, and each is therefore individually more "likely" under the random-order interpretation, even though there are combinatorially more subsets of middling size overall.

### 2.4 Efficiency check

A defining property (see Axiom 1 below) is that the phi_i values sum exactly to the value of the grand coalition minus the baseline:

```
sum_{i=1}^{n} phi_i = v(N) - v(empty set)
```

In the ML setting this becomes: the sum of all features' SHAP values equals `f(x) - E[f(X)]`, i.e., the model's prediction on this exact input minus its average prediction over the data distribution. This is what makes SHAP values "additive" and directly usable in waterfall-style explanations (see Section 6).

## 3. The Four Axioms That Uniquely Characterize the Shapley Value

Shapley did not merely propose a formula — he proved that it is the **unique** value function satisfying four natural fairness axioms. This is the mathematical reason Shapley values are treated as a principled, non-arbitrary attribution scheme rather than "yet another heuristic." Any allocation rule that respects these four common-sense properties of fairness *must* be the Shapley value — there is no other function that does.

### Axiom 1 — Efficiency (a.k.a. "Local Accuracy" in the SHAP literature)

The total payoff is fully distributed among the players; nothing is lost and nothing is invented:

```
sum_{i in N} phi_i = v(N)
```

(In the ML formulation with a baseline, this is `sum_i phi_i = v(N) - v(empty set)`.) This guarantees that feature attributions in SHAP are never a lossy approximation of "why the model predicted what it predicted" — they exactly reconstruct the model's output from the baseline plus the sum of contributions.

### Axiom 2 — Symmetry (Fairness among equals)

If two players `i` and `j` contribute identically to every coalition that excludes both of them, i.e.

```
v(S union {i}) = v(S union {j})   for every S subseteq N \ {i, j}
```

then they must receive identical payoffs: `phi_i = phi_j`. No player can be favored or penalized based on labeling, identity, or position — only based on the actual contribution they make. In ML terms: two features that are functionally interchangeable with respect to the model's output must receive equal credit, regardless of which column came first in the dataset or what the feature is named.

### Axiom 3 — Null Player / Dummy Axiom (Zero credit for zero contribution)

If a player `i` never changes the value of any coalition it joins,

```
v(S union {i}) = v(S)   for every S subseteq N \ {i}
```

then `phi_i = 0`. A feature the model never actually uses (in the sense of never changing the output regardless of what other features are present) receives exactly zero attribution — not a small nonzero noise term, but exactly zero, by axiom. This is what allows SHAP to correctly assign zero importance to irrelevant / unused features, even ones that a naive correlation-based importance metric might flag due to confounding.

### Axiom 4 — Additivity / Linearity

If two separate games with characteristic functions `v_1` and `v_2` (played over the same player set) are combined into a single game `v = v_1 + v_2`, then each player's Shapley value in the combined game is the sum of their values in the two separate games:

```
phi_i(v_1 + v_2) = phi_i(v_1) + phi_i(v_2)
```

This means Shapley values compose linearly. Practically, this is what lets you take an ensemble model that is a (possibly weighted) sum of sub-models — e.g., a random forest is an average of trees, or a boosted model is a sum of weak learners — and compute the Shapley value of the ensemble as the corresponding linear combination of the Shapley values of the components. TreeSHAP's tractability partly rests on this property applied tree-by-tree.

### 3.1 Why the uniqueness theorem matters

**Shapley's theorem:** these four axioms determine one, and only one, value allocation function — the formula given in Section 2. This is a genuine uniqueness result, not just "a reasonable formula that happens to satisfy nice properties." It means:

- You cannot construct a *different* attribution rule that also satisfies Efficiency + Symmetry + Null Player + Additivity. The Shapley formula is forced by these requirements, not chosen by convention.
- When SHAP is described as having "game-theoretically optimal" or "unique fair" attributions, this is the precise mathematical claim being invoked — not a marketing statement. If you accept the four axioms as the definition of "fair credit assignment," accepting the conclusion (the Shapley formula) is logically forced.
- Critically, this distinguishes Shapley-based feature attribution from other feature-importance heuristics (permutation importance, split-count-based importance in trees, raw coefficient magnitude in linear models, gradient saliency, attention weights — see Section 7) which generally do **not** satisfy all four properties simultaneously, and hence can produce misleading or inconsistent attributions in edge cases (e.g., assigning nonzero importance to a feature the model provably ignores, or splitting credit unevenly between two features the model treats identically).

## 4. From Game Theory to Machine Learning: SHAP

**SHAP (SHapley Additive exPlanations)**, introduced by Lundberg and Lee (2017, *"A Unified Approach to Interpreting Model Predictions"*), is the application of Shapley values to explain individual predictions of any machine learning model. The mapping from cooperative game theory to ML feature attribution is:

| Game theory | SHAP / ML |
|---|---|
| Player `i` | Input feature `i` (e.g., "age," "income," "credit score") |
| Player set `N` | The full feature vector `x = (x_1, ..., x_n)` |
| Coalition `S` | A subset of features "known" / "present," the rest treated as absent/marginalized |
| Characteristic function `v(S)` | Expected model output given only the features in `S` are known: `v(S) = E[f(X) \| X_S = x_S]` |
| Grand coalition value `v(N)` | The model's actual prediction on the full input: `f(x)` |
| Empty coalition value `v(empty set)` | The model's baseline / expected prediction: `E[f(X)]` |
| Payoff to distribute | `f(x) - E[f(X)]` — how far this particular prediction deviates from the average prediction |
| Shapley value `phi_i` | The SHAP value of feature `i` for this specific input `x` |

### 4.1 The SHAP value function

Substituting into the Shapley formula, the SHAP value of feature `i` for a specific instance `x` is:

```
                              |S|! (n - |S| - 1)!
phi_i(x) =    sum        ---------------------------  *  [ v(S union {i}) - v(S) ]
          S subseteq F\{i}              n!
```

where `F` is the full set of `n` features, and

```
v(S) = E[ f(X) | X_S = x_S ]
```

i.e., the expected output of the model when the features in `S` are fixed to their actual values from `x`, and the remaining features are treated as random (drawn from their marginal or conditional distribution — different SHAP variants make different choices here, discussed below).

### 4.2 Efficiency in the SHAP setting

The Efficiency axiom (Section 3, Axiom 1) becomes, in SHAP's terminology, the **local accuracy** property:

```
f(x) = E[f(X)] + sum_{i=1}^{n} phi_i(x)
```

This is the single most important practical property of SHAP: for any given prediction, the baseline plus the sum of all feature SHAP values *exactly reconstructs* the model's actual output. This is precisely what makes waterfall/force plots (Section 6) mathematically honest — every bar you see literally adds up to the final prediction, with no residual or unexplained gap.

### 4.3 "Absent" features and the practical difficulty of `v(S)`

The one subtlety that game theory doesn't have to deal with, but ML feature attribution does, is: **what does it mean for a feature to be "absent" from a coalition?** In the taxi-company example, "player A absent" simply means player A isn't there. But a trained ML model `f` is a fixed function that expects *all* `n` features as input — you cannot literally call `f` with only 3 of 10 features "removed." SHAP handles this by **defining** `v(S)` as a conditional (or marginal) expectation:

```
v(S) = E_{X_{F \ S}} [ f(x_S, X_{F \ S}) ]
```

i.e., the features in `S` are held fixed at the instance's actual values `x_S`, and the remaining features `F \ S` are marginalized out — replaced by their distribution over the background dataset (sampled, averaged over, or replaced by their expected value, depending on the implementation). This "marginalization" step is exactly where the different practical SHAP algorithms (KernelSHAP, TreeSHAP, DeepSHAP) diverge in their assumptions and approximations — see Section 5.

## 5. Why Exact Computation Is Intractable, and the Practical Approximations

### 5.1 The combinatorial explosion

Computing the exact Shapley value for a single feature `i` requires evaluating `v(S)` for **every subset `S subseteq F \ {i}`** — there are `2^(n-1)` such subsets. Computing exact Shapley values for *all* `n` features requires evaluating `v(S)` for every subset of `F`, of which there are `2^n`. For `n = 20` features, that's `2^20 ≈ 1,048,576` model evaluations; for `n = 100` features (not unusual in tabular ML), it's `2^100`, which is astronomically infeasible. Each `v(S)` evaluation may itself require averaging the model output over many background samples to approximate the conditional expectation, multiplying the cost further. Exact Shapley computation is, in general, **#P-hard** — it is provably intractable for arbitrary characteristic functions as `n` grows, so approximation (or structural exploitation) is mandatory for any real model.

### 5.2 KernelSHAP — model-agnostic, via weighted linear regression

KernelSHAP (Lundberg & Lee, 2017) reframes the Shapley value computation as a **weighted least-squares linear regression problem**, which admits an efficient approximate solution without touching the internals of the model — it treats `f` as a black box, calling it only through predictions.

The key theoretical result behind KernelSHAP is that the Shapley values are exactly the solution to the following weighted regression:

```
minimize over phi_0, phi_1, ..., phi_n:

   sum_{S subseteq F} pi_x(S) * [ v(S) - phi_0 - sum_{i in S} phi_i ]^2

subject to:  phi_0 = v(empty set),   phi_0 + sum_{i=1}^{n} phi_i = v(F)
```

where the **Shapley kernel weighting** is:

```
pi_x(S) = (n - 1) / [ C(n, |S|) * |S| * (n - |S|) ]
```

for `0 < |S| < n` (and the weight is effectively infinite, i.e., a hard constraint, at `|S| = 0` and `|S| = n`, which is what enforces the Efficiency constraint). This weighting again upweights very small and very large coalitions (which are "cheaper"/more informative about individual marginal effects) and downweights mid-sized coalitions.

**Algorithm outline:**
1. Sample a manageable number of coalitions `S` (rather than all `2^n`), weighted according to `pi_x(S)`.
2. For each sampled `S`, estimate `v(S) = E[f(X) | X_S = x_S]` by averaging model predictions over background data with the "in-coalition" features fixed to `x`'s values and the rest replaced by values drawn from the background dataset.
3. Solve the weighted linear regression above (a closed-form weighted least squares problem) to obtain the estimated `phi_i` for each feature.

KernelSHAP is **model-agnostic** — it works on any `f` (SVM, gradient-boosted trees, neural nets, ensembles, arbitrary pipelines) because it only needs to query `f`'s outputs. The tradeoff is that it's an approximation (sampling-based) and can be computationally expensive for high-dimensional inputs or when many samples are needed for accuracy, and its accuracy depends on the choice and size of the background dataset used to approximate the marginal/conditional distribution.

### 5.3 TreeSHAP — exact, polynomial-time, tree-specific

TreeSHAP (Lundberg, Erion & Lee, 2018/2020) is a **model-specific but exact** algorithm for tree-based models (decision trees, random forests, gradient-boosted trees such as XGBoost, LightGBM, CatBoost). It exploits the recursive, discrete structure of a decision tree to compute exact SHAP values in **polynomial time**, rather than the exponential time exact computation would otherwise require.

The core insight: in a tree, at each internal node the "coalition" question ("is feature `i`'s value known or not") only matters if the split at that node uses feature `i`. TreeSHAP performs a single recursive traversal of the tree(s), tracking, for every root-to-leaf path, the combinations of features observed along the path and their downstream implications, and combines these using a specialized dynamic-programming scheme over subsets of "path features," rather than enumerating all `2^n` global feature subsets. The published complexity for a single tree of depth `d` (across all features and all subsets implicitly represented along paths) is:

```
O(T * L * D^2)
```

where `T` is the number of trees, `L` is the maximum number of leaves in a tree, and `D` is the maximum depth — a dramatic reduction from `O(T * L * 2^D)` for the naive exact approach, and crucially **independent of `2^n`** in the number of input features overall. Because gradient-boosted ensembles and random forests are (weighted) sums of individual trees, the Additivity axiom (Section 3, Axiom 4) lets TreeSHAP compute exact Shapley values per tree and simply sum them across the ensemble.

TreeSHAP's key practical advantages over KernelSHAP: it is **exact** (no sampling noise), it is **fast enough for production use** on large tabular datasets, and it additionally supports computing **SHAP interaction values** (a generalization that attributes pairwise interaction effects between features, based on the Shapley interaction index). Its limitation is that it only applies to tree ensembles — it cannot be used on neural networks, linear models, or other model families without modification.

### 5.4 DeepSHAP and gradient-based approximations for deep networks

For neural networks, exact or sampling-based coalition enumeration is generally too slow because of the model's size and the number of forward passes required. **DeepSHAP** (from the same SHAP framework) adapts the **DeepLIFT** algorithm — which propagates "contribution scores" backward through a network's layers relative to a reference/baseline activation — and recombines DeepLIFT's per-layer attribution rules with Shapley-value composition rules, producing an approximation of SHAP values that is efficient to compute via a small number of backward passes rather than combinatorial coalition sampling.

This connects directly to **Integrated Gradients** (Sundararajan et al., 2017), a separate but closely related attribution method for differentiable models:

```
IntegratedGrad_i(x) = (x_i - x'_i) * integral_{alpha=0}^{1} [ d f(x' + alpha * (x - x')) / d x_i ] d alpha
```

where `x'` is a baseline input (e.g., all-zeros, or a blurred/blank image). Integrated Gradients accumulates the gradient of the model's output with respect to input `i` along a straight-line path from the baseline `x'` to the actual input `x`. It satisfies an axiom directly analogous to Shapley's Efficiency/local-accuracy axiom — called **Completeness** — namely that the sum of all features' integrated gradients equals `f(x) - f(x')`, exactly mirroring the SHAP additivity property. In fact, Integrated Gradients can be shown to be the unique path-based attribution method satisfying Completeness and Symmetry-like axioms along a specific path, and is mathematically related to (though not identical to) an "Aumann-Shapley value" — a continuous generalization of the Shapley value to games with a continuum of players (or infinitesimal players), which is the natural analogue when treating feature *magnitude* rather than feature *presence/absence* as the coalition-forming variable. This is why Integrated Gradients and DeepSHAP are frequently discussed together as approximate, gradient-based cousins of the same underlying Shapley-value idea, adapted for the specific structure of differentiable deep networks.

### 5.5 Summary comparison

| Method | Model class | Exact or approximate | Core mechanism | Typical cost |
|---|---|---|---|---|
| Exact Shapley | Any (black-box) | Exact | Enumerate all `2^n` coalitions | `O(2^n)` — infeasible beyond small `n` |
| KernelSHAP | Any (black-box) | Approximate | Weighted linear regression over sampled coalitions | Tunable (sample count), model-agnostic |
| TreeSHAP | Tree ensembles (XGBoost, LightGBM, random forests, CatBoost) | Exact | Dynamic programming over tree paths | `O(T L D^2)` — fast, exact, production-grade |
| DeepSHAP / Integrated Gradients | Differentiable networks | Approximate | Backpropagation-based contribution propagation / path integral of gradients | A handful of forward/backward passes |

## 6. Reading SHAP Output in Practice

SHAP output is used at two distinct levels: **local** explanations (a single prediction) and **global** explanations (aggregate behavior of the model across a dataset).

### 6.1 Local explanations: waterfall and force plots

For a single input `x`, SHAP produces one `phi_i(x)` per feature, satisfying:

```
f(x) = E[f(X)] + phi_1(x) + phi_2(x) + ... + phi_n(x)
```

A **waterfall plot** (or **force plot**) visualizes this decomposition directly:

- It starts at the baseline value `E[f(X)]` (the model's average prediction over the background/training data).
- Each feature is drawn as a bar (or arrow) that pushes the running total either up (positive `phi_i`, the feature increased the prediction relative to baseline for this instance) or down (negative `phi_i`, the feature decreased it).
- Features are typically sorted by the magnitude of `|phi_i(x)|`, so the most influential features for *this specific prediction* appear first.
- The bars, stacked in sequence from the baseline, land exactly on `f(x)`, the model's actual output for this input — this is the local accuracy / Efficiency guarantee made visible.

This answers the question: *"Why did the model predict this particular value for this particular input?"* — e.g., "the model predicted this customer has 78% churn probability; the baseline churn rate is 25%; +30 points came from `tenure_months = 2`, +15 points from `monthly_charges = 95`, -8 points from `has_autopay = True`," etc., all of which sum exactly back to 78%.

### 6.2 Global explanations: mean absolute SHAP value

To understand overall **feature importance** across an entire dataset (not just one prediction), compute the mean absolute SHAP value per feature over `m` instances:

```
Importance_i = (1/m) * sum_{k=1}^{m} |phi_i(x^(k))|
```

Ranking features by `Importance_i` gives a global feature-importance ranking that is more theoretically grounded than, e.g., raw split-count importance in trees (which can be biased toward high-cardinality features) or the magnitude of linear-model coefficients (which ignores feature scale and doesn't account for correlations or nonlinear interactions the model may have learned).

### 6.3 Summary plots

A **SHAP summary plot** (often a "beeswarm" plot) displays, for every feature (rows, sorted by global importance) and every instance in the dataset (individual points), the SHAP value `phi_i(x^(k))` on the x-axis, with the point's color typically representing the feature's raw value (e.g., red = high feature value, blue = low feature value). This single plot conveys, at a glance:

- **Global importance** (features at the top have the widest spread / largest mean absolute SHAP values).
- **Direction of effect** (points clustered on the positive side push predictions up; on the negative side, down).
- **The nature of the relationship** — e.g., if high feature values (red points) cluster on the positive-SHAP side and low values (blue) cluster on the negative side, that indicates a monotonically positive relationship between the feature and the prediction; a mixed/scattered color pattern indicates a more complex, possibly non-monotonic or interaction-driven relationship.

### 6.4 Dependence plots

A **SHAP dependence plot** plots, for one specific feature `i`, the feature's raw value `x_i^(k)` on the x-axis against its SHAP value `phi_i(x^(k))` on the y-axis, across all instances `k` in the dataset. This reveals the shape of the feature's learned effect — e.g., a roughly linear cloud indicates the model learned an approximately linear relationship with that feature; a curved or non-monotonic cloud reveals a threshold effect or a nonlinearity the model has captured. Points are frequently colored by a second feature (chosen automatically as the feature that most strongly interacts with `i`, or manually) to reveal **interaction effects** — vertical dispersion in the cloud at a fixed `x_i` value that correlates with the coloring feature indicates that feature `i`'s effect on the prediction depends on the value of the coloring feature.

## 7. Shapley Values vs. Attention Weights: Interpretability in the LLM Era

With the rise of transformer-based LLMs, **attention weights** are frequently presented — informally, and sometimes in published work — as a form of "explanation": the argument being that if a model attends heavily to token `t` when producing an output, then token `t` must have been influential in producing that output. This intuition is appealing but **not rigorously justified**, and it is worth contrasting explicitly with Shapley-value-based attribution:

- **Attention weights lack any axiomatic guarantee.** There is no theorem analogous to Shapley's uniqueness result establishing that attention weights satisfy Efficiency, Symmetry, Null Player, or Additivity with respect to the model's actual output. A token can receive a high attention weight in one layer/head while having little or no causal effect on the final prediction (its contribution may be canceled out downstream, or the represented information may already be redundant with other tokens), and conversely a token with low attention weight can still be functionally critical. Multiple published studies ("Attention is not Explanation," Jain & Wallace, 2019; "Attention is not not Explanation," Wiegreffe & Pinter, 2019) have shown that attention distributions can be substantially altered — sometimes adversarially — without materially changing the model's output, which is inconsistent with treating raw attention as a faithful causal explanation.
- **Attention is a single internal signal, not an end-to-end attribution.** A modern transformer has many attention heads across many layers, plus MLP blocks, residual connections, layer norms, and (in decoder-only LLMs) autoregressive token-by-token generation. Raw attention weights from any one head/layer reflect only a local computation internal to that block; they do not, by construction, account for how information is subsequently transformed, combined, suppressed, or amplified by the rest of the network before it reaches the output layer.
- **Shapley-value-based attribution, by contrast, is defined directly in terms of the model's actual output** — it treats the whole model as a black-box characteristic function `v(S) = E[f(X) | X_S = x_S]` and measures the causal effect of *including* a given input token (or feature) on the final prediction, averaged fairly over all possible token/feature coalitions. It carries the four-axiom guarantee regardless of the model's internal architecture — it does not matter whether the "player" contributes via attention, via a residual stream, via an MLP, or via some other internal mechanism; only the effect on the final output counts.

The practical tradeoff is cost versus faithfulness: attention weights are essentially free (already computed as part of the forward pass) but carry no guarantee of reflecting true output-level importance; Shapley-based methods are faithful to the actual model output by construction but require running many (or, for KernelSHAP-style estimators, cleverly sampled) additional coalition evaluations, which is expensive for LLMs given their size and the combinatorial number of possible token subsets in a long input.

**Token-level Shapley attribution for LLMs** is an active and growing area of application, treating each input token (or token span/word) as a "player" and the LLM's output (e.g., the probability assigned to a specific generated token, or a downstream classification/scoring head) as the payoff. Because exact computation over `2^n` token coalitions is infeasible for realistic prompt lengths, practical implementations rely on the same approximation strategies discussed in Section 5 — sampling-based KernelSHAP-style estimators, or gradient-based approximations analogous to DeepSHAP/Integrated Gradients applied over the embedding or token dimension — adapted to sequential, autoregressive generation (e.g., attributing the probability of a specific generated span back to specific input tokens, or explaining a retrieval-augmented generation system's output in terms of which retrieved passages/tokens were causally responsible). This gives a genuinely causal, axiom-grounded notion of "which input tokens mattered," in contrast to reading raw attention heatmaps and assuming they answer the same question.

## 8. Worked Numerical Example

Consider a toy model with three binary features — `A`, `B`, `C` — each either "present" (its actual value from a specific instance `x`) or "absent" (replaced by a baseline/background value). Define the characteristic function `v(S)` as the model's expected output when exactly the features in `S` are set to their real values (and the rest are held at baseline). Suppose, for this particular instance, the model's behavior gives us the following table of `v(S)` for all 8 subsets of `{A, B, C}` (these are simple made-up numbers chosen to keep the arithmetic clean):

| Coalition `S` | `v(S)` |
|---|---|
| `{}`          | 10 |
| `{A}`         | 14 |
| `{B}`         | 12 |
| `{C}`         | 16 |
| `{A,B}`       | 19 |
| `{A,C}`       | 22 |
| `{B,C}`       | 21 |
| `{A,B,C}`     | 28 |

We want the **Shapley value of feature `A`**, `phi_A`. There are `n = 3` players, so there are `3! = 6` orderings. Enumerate all 6 orderings and compute `A`'s marginal contribution — the value added by `A` joining, given whoever is already present — in each one:

| Ordering | Coalition before `A` joins, `S` | `v(S)` | `v(S ∪ {A})` | Marginal contribution of `A` |
|---|---|---|---|---|
| A, B, C | `{}` | 10 | 14 | `14 - 10 = 4` |
| A, C, B | `{}` | 10 | 14 | `14 - 10 = 4` |
| B, A, C | `{B}` | 12 | 19 | `19 - 12 = 7` |
| C, A, B | `{C}` | 16 | 22 | `22 - 16 = 6` |
| B, C, A | `{B,C}` | 21 | 28 | `28 - 21 = 7` |
| C, B, A | `{B,C}` | 21 | 28 | `28 - 21 = 7` |

Average these six marginal contributions:

```
phi_A = (4 + 4 + 7 + 6 + 7 + 7) / 6 = 35 / 6 ≈ 5.833
```

**Cross-check using the subset-weighted formula.** For `n = 3`, `A`'s possible predecessor subsets `S subseteq {B, C}` are `{}`, `{B}`, `{C}`, `{B,C}`, with sizes `0, 1, 1, 2`. The weight for a subset of size `s` is `s!(n-s-1)!/n! = s!(2-s)!/6`:

- `s=0`: weight `= 0! * 2! / 6 = 1*2/6 = 1/3`
- `s=1`: weight `= 1! * 1! / 6 = 1*1/6 = 1/6`
- `s=2`: weight `= 2! * 0! / 6 = 2*1/6 = 1/3`

Applying these weights to `A`'s marginal contribution for each subset:

```
phi_A =  (1/3)*[v({A}) - v({})]        <- S = {}
       + (1/6)*[v({A,B}) - v({B})]     <- S = {B}
       + (1/6)*[v({A,C}) - v({C})]     <- S = {C}
       + (1/3)*[v({A,B,C}) - v({B,C})] <- S = {B,C}

      = (1/3)*(14-10) + (1/6)*(19-12) + (1/6)*(22-16) + (1/3)*(28-21)
      = (1/3)*4        + (1/6)*7       + (1/6)*6       + (1/3)*7
      = 1.333          + 1.1667        + 1.0           + 2.333
      = 5.833
```

Both methods agree: **`phi_A ≈ 5.833`**. Following the identical procedure for `B` and `C`:

```
phi_B = (1/3)*(12-10) + (1/6)*(19-14) + (1/6)*(21-16) + (1/3)*(28-22)
      = (1/3)*2 + (1/6)*5 + (1/6)*5 + (1/3)*6
      = 0.667 + 0.833 + 0.833 + 2.0
      = 4.333

phi_C = (1/3)*(16-10) + (1/6)*(22-14) + (1/6)*(21-12) + (1/3)*(28-19)
      = (1/3)*6 + (1/6)*8 + (1/6)*9 + (1/3)*9
      = 2.0 + 1.333 + 1.5 + 3.0
      = 7.833
```

**Efficiency check:** `phi_A + phi_B + phi_C = 5.833 + 4.333 + 7.833 = 18.0`, and indeed `v({A,B,C}) - v({}) = 28 - 10 = 18`. The three features' fair shares sum exactly to the total gain over baseline, exactly as the Efficiency axiom requires — no residual, no double-counting.

In SHAP terms: if this were a real model, `v({}) = 10` is the baseline/expected prediction `E[f(X)]`, `v({A,B,C}) = 28` is the actual prediction `f(x)` for this instance, and the three SHAP values `(5.833, 4.333, 7.833)` tell us that, of the 18-point gap between this prediction and the average prediction, feature `C` is responsible for the largest fair share (7.833 points), followed by `A` (5.833), then `B` (4.333) — a complete, additive, axiomatically-justified local explanation of this single prediction.

## 10. Summary

Shapley values began as a solution to a fairness problem in cooperative game theory: given a coalition that jointly produces some value, split the payoff among players in a way that respects four intuitively necessary properties — Efficiency, Symmetry, the Null Player property, and Additivity — properties strong enough that they force a single, unique formula. SHAP repurposes this formula for machine learning by treating input features as "players" and the model's prediction (relative to a baseline) as the "payoff," yielding feature attributions that are additive, consistent, and provably fair with respect to the model's actual behavior — not just plausible-looking heuristics. Because exact computation requires evaluating all `2^n` feature coalitions, practical SHAP relies on approximations tailored to model class: KernelSHAP's weighted-regression sampling for arbitrary black-box models, TreeSHAP's exact polynomial-time dynamic program for tree ensembles, and DeepSHAP/Integrated-Gradients-style gradient propagation for differentiable networks. In practice, SHAP values support both local explanations (waterfall/force plots showing why one specific prediction landed where it did) and global explanations (mean absolute SHAP value as a theoretically grounded feature-importance ranking, visualized via summary and dependence plots). In the LLM era, this axiomatic foundation is precisely what raw attention weights lack — attention can be manipulated without changing model output and carries no guarantee of reflecting true causal importance, which is why Shapley-based token attribution, despite its computational cost, is emerging as the more rigorous tool for explaining what an LLM's output is actually attributable to.
